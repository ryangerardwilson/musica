## Context

The player is one Bubble Tea `model` in `internal/app`. The TUI runs it on a terminal and holds the musica session: a lock and the control socket `$XDG_RUNTIME_DIR/musica/control.sock`, whose only command today is `end`. The Super+T launcher is a Quickshell shell. It can open a unix socket and split lines, and it must not read sqlite or hyprctl.

## Decisions

**One model, two front ends.** `musica serve` runs the same `model` under a Bubble Tea program with no renderer and no input. Keys arrive from the socket as `tea.KeyMsg`, so the cassette list, the cassette menu, search, rename, create, delete, shuffle, seek, restart, stop, the YouTube prompts, the download view, and their wrap rules stay one implementation. A wrapper publishes a frame after each update. The model's own `View` is not built.

**The socket stays one socket.** It stays line based. `end` is answered `ok` as before. `watch` turns the connection into a stream with no deadline: the server writes one JSON object per line and reads one JSON object per line. Each watcher has a bounded queue; a watcher whose queue fills is dropped so a stuck client never stalls the player. Only a served session takes `watch`; the TUI answers `unknown command`, so the launcher knows that session will not stream and takes it over.

**A terminal session is taken over.** The launcher cannot draw a TUI session, and a TUI from an older musica understands only `end`. Before `musica end` sends `end`, it reads the listener's pid from the socket (`SO_PEERCRED`), finds that process's `ffplay` child in `/proc`, and keeps ffplay's last argument, the track, in `$XDG_RUNTIME_DIR/musica/held`; with no ffplay it removes an older note. It then returns only once the session has let go of its lock, trying the lock every 50 ms for up to five seconds. A paused ffplay is a stopped process that ignores SIGTERM until the TUI kills it, so a terminal session lets go in a little over a second. `musica serve` takes the note once it holds the session and opens that track's cassette with the track selected, the menu open, and the frame state `paused` with no time. It does not start ffplay: neither the TUI's process clock, which counts the hours ffplay was stopped, nor ffplay's command line, which has no `-ss`, says where it was. Space says there is nothing to resume, Enter plays the track from the start, and `x` puts it down. A missing track is skipped.

**First frames do not wait on the store.** `musica serve` resumes queued downloads beside the player rather than before it, so a watcher gets a frame within a tick of the socket opening. The launcher treats a session that sends no frame for three seconds as one that will not stream.

**Frames carry what the center draws.** The playing state, elapsed time, and title; the status line; the view, the open cassette, and up to nine rows around the selection with their slot, kind, name, and whether they are playing; the prompt kind and text; help; the download view, its rows, and its selection; the 32 band `levels` and `peaks` after the model's start and track-change easing; and `bass` (the low fifth of the bands) and `energy` (all bands), each 0 to 1. A frame is built only while someone watches. The model ticks at the config FPS, 20 by default, and the analyzer reads a new window about 11 times a second, so the launcher eases between frames. `thump` is not eased: it is the hardest kick since the frame before, kept until a frame takes it. The analyzer hears the bands under 170 Hz in windows that overlap by half, so a kick across a window's edge is heard whole, and counts the rise over the louder of the slow mean and what is left of the windows before, so a held tone hits once. Each update takes it, watched or not, so a frame never carries an older one.

**Leaving is the model's call.** In a served player `m`, and Escape from anywhere, send `leave` instead of toggling the menu or running `MUSICA_HIDE_COMMAND`. Escape backs out of nothing there: the center closes the whole Super+T menu on Escape and sends nothing, so a prompt, help, the download view, or an open cassette waits for the next showing. `h` is the way back: from a cassette's tracks, help, or the download view it shows the cassette list with that cassette selected, and on the cassette list it moves as in the TUI. The terminal TUI keeps Escape as back and `h` as up. The model decides in key order, so `/` followed at once by `m` types `m` into the search and does not close the center. `q` and Ctrl+C quit as in the TUI: playback stops, the server sends `ended`, closes the socket, and exits.

**Bare musica asks the launcher.** It runs `<config>/quickshell/omarchy-launcher/open.sh musica`, `<config>` being `$XDG_CONFIG_HOME` when it is absolute and `~/.config` otherwise. The launcher starts `musica serve` when it cannot connect, so there is one starter. `player.Run` with no arguments does the same, which is how `r2d2 musica` reaches the center.

## Risks / Trade-offs

- A served session keeps its 500 ms download poll while it lives, as the hidden TUI popup did. It ends on `q`, Ctrl+C, `musica end`, SIGTERM, SIGINT, or SIGHUP, and stops ffplay and ffmpeg first.
- r2d2 opens the center itself for bare `r2d2 musica`, so it does not wait on a pin bump. Until the pin moves, `r2d2 musica end` runs the pinned `End`, which neither waits nor notes the track; the launcher runs the musica binary's `end`.
- The held note is one line in the runtime directory. A note left by a `musica end` typed by hand opens that cassette paused at the next `musica serve`, however much later; logging out or rebooting clears it.
- The launcher path is this desktop's convention. When it is missing, bare `musica` fails and names the path; `musica play` and `musica open` still open the TUI.
